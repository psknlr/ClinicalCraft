# Engine, lint and doc changes the case reviewers reported (v6 rounds, 2026-11-14)

- cmcr-1069544 r3: packages/core/src/engine/negation.ts: a Chinese negation cue directly before Latin letters is not read. 不做ERCP, 不要做ERCP and 暂不做ERCP give negated:false (affirmative '做ercp'), while 不做手术 is read correctly. As a result matchInterventions returns the declined act; here urgent-ercp, which is critical: true, so the safety outcome fails for a learner who declined it. cmcr-1069544 guards it with urgent-ercp excludeKeywords (不做, 不要做, 别做, 不用做, 不需做) until a central fix lands.
- cmcr-1069544 r3: packages/core/src/engine/negation.ts / matcher.ts: a negation cue separated from a polar item phrase by a verb and object is not read as a double negative. "don't keep her nil by mouth", "do not keep…" and "no need to keep…" return nil-by-mouth at 1.00 and also withhold unrelated items (oral-calcium via 'by mouth', lab-query-repeat). 解除禁食 (lift the fasting) returns nil-by-mouth (解除 is not a cue), whereas "she doesn't need to be nil by mouth" and 停止禁食 are read as double negatives. cmcr-1069544 guards it with nil-by-mouth excludeKeywords.
- cmcr-33555 r3: core matcher (packages/core/src/engine/matcher.ts): an intervention's excludeKeywords should not fire on a word that sits in a negated clause (analyzeNegation). Today 'No ceftriaxone, give cefotaxime and ampicillin' returns nothing for cmcr-33555 because the antibiotics item excludes 'ceftriaxone'; the exclusion itself is needed so that 'ceftriaxone with ampicillin' does not resolve to the key.
- cmcr-33555 r3: scripts/case-check.ts (optional): its plain-opener probe could also try 'What made you bring him here?', 'When did he first become unwell?' and 他生病几天了？. All three reached nothing in this case before round 3's keywords; they likely do in other cases too.
- cmcr-1069544 r4: Core negation reader (analyzeNegation / interventionNegation): a Chinese negation cue before Latin letters is not read as negating the item. Examples: 没必要做ERCP, 没有必要做ERCP, 不必做ERCP, 不能做ERCP, ERCP没有指征 (round 3 reported 不做ERCP / 不要做ERCP). The order resolves to the critical intervention. This case guards with excludeKeywords; the excludes can go once the reader is fixed.
- cmcr-1069544 r4: Core intervention matcher: the query word 'ring' matches the alias 'ringer' (lactated Ringer's), so 'ring the laboratory' and 'give the lab a ring' resolved to the fluid. This case guards with excludeKeywords (lab, laboratory, ring the, a ring); a matcher fix (no stem or prefix match of 'ring' to 'ringer') would remove the need for them.
- cmcr-1069544 r4: Collection contract: the cross-case test 'is not a template: no teaching text is shared by more than two cases' currently fails. All 53 offending texts belong to 34 untouched 1.0.0 template cases (e.g. cmcr-1067475); none involve cmcr-1069544. Recorded so the integration does not attribute it to this case.
- cmcr-33555 r4: Web treat tab (packages/web/src/ui/panels/conversation.ts treat()): every intervention's name and dose text is listed from the start of a case. In cmcr-33555 this shows decision 1's and decision 5's keys and later-phase items (maternal liaison with 'any treatment of hers … not stopped abruptly', safeguarding, gastric lavage, charcoal, repeat exchange) before the learner reaches them. Suggest listing only search results, hiding dose texts until an item is given, or a per-intervention visibility condition. This is library-wide.
- cmcr-33555 r4: Core matcher (scoreNegated in packages/core/src/engine/matcher.ts): intervention excludeKeywords are tested against the whole utterance (u.full.compact), negated clauses included, so a negated trap name suppresses the key ('Give cefotaxime, not ceftriaxone'). cmcr-33555 now works around this with combination-form exclusions; applying exclusions to the affirmative clauses only would fix it for every case.
- cmcr-44362 r1: matchOrders (packages/core/src/engine/matcher.ts) matches order aliases as substrings of the whitespace-stripped query. Short ASCII aliases therefore fire inside ordinary words ('tte' in 'better'/'pattern', 'rf' in 'perform'), and in this case an unrelated order could earn a critical item. Suggest a `cases validate --strict` lint that flags (a) ASCII order aliases of 3 letters or fewer, or aliases found inside a list of common English words, and (b) any alias of one investigation that is a substring of another investigation's alias in any locale (e.g. '关节片' inside '髋关节片'). Alternatively, matchOrders could require word boundaries for ASCII aliases. The same class probably exists in other cases.
- cmcr-44362 r2: Matcher (packages/core/src/engine/matcher.ts): a greeting ('Good morning', '早上好') is scored as content. Any history item keyed on 'morning'/'早上' then ties at 1.0 with the learner's real question and wins by declaration order. Stripping common greetings before scoring would fix this for the whole library; cases can only work around it with excludeKeywords, as this one now does.
- cmcr-44362 r2: Content lint: flag order aliases that are bare common words or occur inside ordinary order phrasing, because matchOrders matches aliases as substrings. This case had 诊断/'diagnosis' (diagnosis record) and 心电 (ECG); round 1 had 'tte' and 'rf'. A lint for aliases contained in another investigation's aliases or in a common-word list would catch the class.
- cmcr-44362 r2: Content lint or engine: an orderable test whose results leave out a phase in which it can be ordered gets its read refused 'no-record' instead of showing 'No result is recorded for this test.' Here the ECG, chest X-ray and FBC lacked a diagnosis-phase entry. Either require an entry for every non-final phase, or have the engine fall back to the not-recorded text.
- cmcr-634927 r1: Matcher (core): 禁食禁饮 / 禁食禁水 / 禁食水 (nil by mouth) is read as a negated order because of 禁, so it cannot reach the intervention whose alias it is (here fluid-restriction) and resolves to 'negated' with no suggestion. Like 不透气 / 不透水 (KIT §3.18), 禁食/禁饮 should be read as order words.
- cmcr-634927 r1: Agent order resolution: one query that names two tests ('paired osmolalities', 'plasma and urine osmolality') resolves to two ids, which counts as ambiguous, so nothing is ordered. An order set (or a case-level 'orders both' rule) would let one plain request order both.
- cmcr-634927 r1: Housekeeping (not a code change): the author's builders work-cmcr-634927/build_case.py and build_parts.py are stale after this review. case.json is now the source, and r1_fix.py re-applies the review from case.before-r1.json.
- cmcr-44362 r3: Core matcher (packages/core/src/engine/text.ts tokensMatch): fuzzy prefix matching (5 shared letters, tail of 3 or fewer) lets procedural verbs match drug aliases, e.g. 'aspirate'/'aspirated' match the alias 'aspirin', so an intervention order for a procedure can resolve to a medication. A case can only work around this with excludeKeywords. Suggest exact matching for medication-name aliases, or a lint flagging intervention aliases that fuzzy-match common clinical verbs (aspirate, aspiration), across the library.
- cmcr-44362 r3: Matcher excludeKeywords are compared against compacted text (whitespace removed), so a Latin exclude such as 'at first' also fires inside 'what first'/'that first'. Word-boundary-aware excludes for Latin phrases would let authors separate look-alike items without breaking plain openers.
- cmcr-44362 r3: Guideline currency, library-wide: the ACR posted its 2026 JIA guidelines on 13 May 2026, updating the ACR/AF 2019 polyarthritis guideline and the ACR 2021/2022 nonpharmacologic guideline. The full manuscripts and DOIs were not found yet. Other cases or docs citing ACR/AF 2019 or ACR 2021 JIA recommendations should be re-checked centrally. No other case in packages/content/cases cites Ringold 2019 or the 2026 summary.
- cmcr-634927 r2: Web Treat tab (packages/web/src/ui/panels/conversation.ts, treat()): it lists every case intervention with its dose text from the first phase. Acts that only make sense later (desmopressin, holding it, 3% saline, a water deprivation test) therefore preview the course and the hidden diagnosis. An intervention-level visibility/availability condition, like investigations' availability.when, or a list showing only searched acts, would let authors stage them.
- cmcr-634927 r2: Agent resolveIntervention (packages/agent/src/tools/clinical-resolve.ts, interventionWords/interventionQuery): a clear-winner id is returned without consulting interventionNegation. 'withhold oral fluids' therefore resolved to an item whose alias held 'withhold fluids' (here the critical test), while negation analysis reported withheld items. A withhold/no/nil verb could prefer the negation reading or a withholding item. The case now avoids it through aliases.
- cmcr-634927 r2: Core matcher excludeKeywords are checked against compact scoring text (spaces and %/symbols removed), so a numeric exclude like '50%' matches inside '250 mL/h' or '150毫升'. In this case it silently sent measured hypotonic orders to a critical act until it was reverted. A content lint warning for exclude phrases that reduce to digits only, or token-boundary matching, would prevent this.
- cmcr-44362 r4: scripts/case-check.ts OPENERS: add openers made only of stop words or a name, such as 'Could you tell me why <name> is here?' and 'What's been bothering him/her?'. These reach nothing unless the author adds run-together keywords, which is the library-wide KIT §3.10 problem this case had.
- cmcr-44362 r4: KIT §3.10 recommends 'how long' as a presenting-complaint keyword, but 'how' is a stop word, so the keyword reduces to the token 'long'. Any question containing 'long' (for example 'a long cough') then hits the presenting complaint at 1.0. Recommend the run-together 'howlong', or a matcher rule for keyword phrases that begin with stop words.
- cmcr-44362 r4: docs/GLOSSARY.md or KIT: render 'more than N' criteria in Chinese as '超过N项（即至少N+1项）', never 'N项以上', because 以上 includes N. A bilingual lint could flag '一项以上' where the English says 'more than one'.
- cmcr-44399 r1: packages/content/src/__fixtures__/completable.ts (stepsThatTrapALateLearner) probes only 'intervene' and 'order' steps. It cannot find an objective that waits for a history item or exam finding limited to early phases (as cmcr-44399's obj-story did). Suggest extending it to 'ask' and 'examine' steps, or adding a lint: an objective's {asked}/{examined} leaf must name an item available in every phase from which the objective can still be completed.
- cmcr-44399 r1: Order matcher (packages/core/src/engine/matcher.ts matchOrders) matches an alias anywhere inside the order. A short alias such as 'che' (inside check/chest/chemistry) or 'bm' (inside submit/BMI) captures unrelated orders. Suggest a strict lint for aliases of 3 or fewer letters that occur inside common words, or matching aliases at token boundaries.
- cmcr-33610 r1: Matcher (packages/core/src/engine/text.ts characterScore): a short phrase that mixes Latin letters and Han characters is scored as CJK. Its two-letter Latin overlaps then score 2/len (0.40 for a 5-character alias such as 'BEP方案'), above MATCH_THRESHOLD 0.34. As a result, ordinary English orders ('Give paracetamol', 'Insert a peripheral cannula', 'Check the pulse') resolved to an unrelated high-risk intervention. Suggested fix: score the Latin runs of mixed phrases by tokens, or require a Han character in the common run. Until then, a lint could flag zh aliases or keywords under 7 characters that contain Latin letters. Other cases may carry such aliases; this case was fixed locally with 7-character aliases.
- cmcr-33610 r1: Citation check: the AAP 2025 policy statement on chaperones (Pediatrics 2025;155(6):e2025071810) could not be read in full text from this environment (publications.aap.org returns a bot challenge; no PMC copy). Someone with browser access should check its recommendations on genital examination of a prepubertal child, so the case's softened attribution ('abstract') can be restored.
- cmcr-44399 r2: Engine matcher (packages/core/src/engine/text.ts tokensMatch): a token of 6 or more letters matches any longer token it begins, so a run-together keyword that starts with a long content word ('prescribedfor') matches any utterance containing that word. The strict lint flags multi-word keywords that reduce to one token, but not run-together ones with this prefix effect. A lint warning, or a CASE_AUTHORING note recommending that run-together keywords start with a short or stop word, would prevent this.
- cmcr-44399 r2: Engine intervention matching: aliases written as a verb plus a drug ('give atropine', 'give charcoal', 'give neostigmine') score 0.5 on the verb alone. So 'Give oxygen', 'Give glycopyrrolate' or 'Give adrenaline' resolve to an ambiguous list that suggests unrelated drugs, including the harmful neostigmine. Round 1 reported this too; weighting generic order verbs down in alias scoring would fix it for every case.
- cmcr-44399 r2: Engine negation handling (matchInterventions / interventionNegation): a mixed order such as 'Give 0.9% saline with 5% dextrose at maintenance, not dextrose saline' withholds the negated item but returns no affirmative item, so the isotonic fluid is not given.
- cmcr-33610 r2: Engine/lint (matcher): tokensMatch treats 'anaesthetist' as the same token as 'anaesthetic' and 'anaesthetise' (long shared prefix, short divergent tail). A one-word role alias on a consult item (e.g. 'anaesthetist' on an anaesthetic review) therefore captures orders to give the anaesthetic itself. In this case that credited a critical safe act for the dangerous order. Suggest a validate --strict warning when a one-token intervention alias fuzzy-matches a token in another intervention's name or aliases, or when an alias of a non-critical consult matches the name of a critical or contraindicated item. Optionally keep agent-noun/drug pairs (-ist vs -ic/-ise/-ia) apart in tokensMatch.
- cmcr-33610 r2: Lint (matcher corpus): an English keyword or alias that reduces to one very common token after stop-word removal ('which was first' -> ['first'], 'pre-anaesthetic' -> ['pre','anesthetic']) silently matches any utterance containing that token. A strict-mode warning for single-token keywords that are frequent question words (first, last, before, after, any) would catch it. The README convention of run-together keywords is not enforced.
- cmcr-44399 r3: Lint (core integrity checkKeywordPhrases / content-standard): (1) A run-together single-token keyword whose leading real word has 6+ letters ('unwellwith', 'broughthimin', 'prescribedfor') is a prefix wildcard under tokensMatch's FREE_PREFIX_LENGTH rule, and nothing warns. (2) Two-word keywords that reduce to one token ('what tablets' → 'tablet') are not flagged, because the rule only checks phrases of 3+ words. Suggest warning on both, or making run-together keywords match by compact containment only.
- cmcr-44399 r3: cases verify (packages/cli/src/cases.ts checkUtterances/withPhaseTwins) does not restrict hits to items available in the expected item's phase, unlike the session pipeline (selectFacts → matchHistory {phase}). A later phase twin with extra keywords can outrank the current-phase item: 'How's your tummy, buddy?' selects child-now-2h in arrival, so a valid regression utterance fails verify. Here it was replaced by 'How are you holding up, buddy?'.
- cmcr-44399 r3: Still open from round 1 (engine-level verb weighting): any 'Give X' order (oxygen, glycopyrrolate, adrenaline) scores about 0.5 on every item with a 'give …' alias, including the critical neostigmine-dose, and comes back as ambiguous suggestions that list a critical harmful act.
- cmcr-33610 r3: Matcher (core, CJK keyword matching): a CJK keyword matches as a substring across the particle 一下 and across a sentence-initial 下面 meaning 'next'. So 一下体温 / 一下体重 / 一下体格 contain 下体, and 一下面部 / 一下面色 / 下面检查… contain 下面, and these route to a genital examination at 1.00. In this case it was fixed with case keywords and excludes, but any other case using 下体 or 下面 as a genital (or other) keyword is probably affected. Suggested central fixes: treat 一下 as a segment boundary, or treat sentence-initial 下面 as a discourse marker, in CJK keyword matching. A lint could also warn about CJK keywords that occur inside very common verb–particle sequences.
- cmcr-33610 r3: Engine/UX (optional): an order placed before the phase that holds its result returns the 'no result at this stage' placeholder, and reading the later phase's result is refused ('not-ordered') until the learner orders it again. A learner who ordered β-hCG or chest imaging early is not told to re-order. Consider carrying a pending order into the phase where its result appears, or a nurse prompt to repeat it. Documented in this case's README timeline; no case change can fix it.
- cmcr-44399 r4: Core negation (packages/core/src/engine/negation.ts, analyzeNegation): some refusals placed after the drug or act leave it outside the negated scope, so matchInterventions returns the harmful item. Measured scopes: 新斯的明不要再吃了 → scope '再吃了'; 新斯的明别吃了 → '吃了'; 出院还不行 → '行'; "Lavage isn't indicated" → 'indicated'. By contrast 新斯的明不要再用了, 活性炭不要给, 洗胃就不要再做了 and 'Lavage is not indicated' are read correctly. Extend the post-posed zh rule to 吃/服/喝 and to 还不行/不行/不能, and treat 'isn't/aren't/wasn't' + predicate like 'is not'. This case works around it with excludeKeywords; other cases with oral drugs will hit the same gap.
- cmcr-44399 r4: Matcher excludeKeywords match as raw substrings of the compact utterance. An exclusion 'continue' also fires on 'discontinue', and 再吃 on 不要再吃, which silently disables the item that withholds. Suggest a lint warning when an item's exclusion is contained in a negation cue plus that word, or negation-aware exclusions.
- cmcr-44399 r4: The `cases verify` utterance check (CLI, matchHistory) and the session's selection (selectFacts + offlineRerank) can disagree. 'Has he ever had a rash with medicines?' passed the session probe but failed verify (associated ranked above allergies). Worth aligning, or documenting which one the corpus tests.
- cmcr-33610 r4: packages/core/src/engine/negation.ts: the English cues (EN_PREDICATE/EN_PARTICIPLE/EN_VERB/EN_PARTICLE) have no 'without', the 'un-…ed' form ('unsedated') or the Chinese 非…/清醒状态下 forms. So matchInterventions scores 'Do the CT without sedation', 'CT chest without anaesthesia' and 非镇静下做CT at 1.00 for a sedation item, 'Proceed to surgery without chemotherapy' at 1.00 for chemotherapy, and 'Manage him without a GnRH analogue' at 1.00 for the GnRH analogue. The resolver auto-resolves these (≥ 0.55), so a safe order performs the harmful act, which is critical in this case. The core should read 'without <X>' as negating what follows, as it already reads 'rather than' and 'instead of'. cmcr-33610 works around it with 'without' exclusions on its harmful interventions. Other cases with harmful interventions are probably affected.
- cmcr-634927 r3: Engine (negation scope, packages/core matchInterventions/interventionNegation): in 'do not restrict her fluids', 'no fluid restriction', 'avoid fluid restriction' the negation is attributed to 'fluids' (a saline alias) and the restricting act itself is returned; cmcr-634927 works around it with excludeKeywords, but the negated verb ('restrict', 'limit') should withhold the act centrally.
- cmcr-634927 r3: Engine (negation lexicon): 禁食禁水 / 禁水 are read as negations (禁 'forbid'), so a nil-by-mouth order does nothing (KIT 3.18 class, like 不透水).
- cmcr-634927 r3: Engine/lint (orderMatching): rules are tested against the whitespace-free normalised order, so a rule regex written with a space ('urine ketone') never fires; `cases validate` could warn on spaces in ifMatches/unlessMatches.
- cmcr-634927 r3: Engine/lint (matchOrders): Latin aliases of 1-2 letters ('ua') match inside unrelated words by substring ('evaluate', 'actual', 'usual'); a lint for very short Latin aliases (or word-boundary matching for them) would prevent silent extra orders.
- cmcr-634927 r3: Engine (matcher): a run-together single-token keyword can score 1.0 against an utterance word that is its prefix ('happenedbefore' matched 'What happened to her today?'); worth a note in CASE_AUTHORING's run-together advice.
- cmcr-634927 r3: CLI (cases verify, checkUtterances): the expected-first check ranks hits without the phase filter (only twins are applied), so a later-phase utterance can fail on an item available only in another phase; filtering by the first expected item's phases would match the pipeline.
